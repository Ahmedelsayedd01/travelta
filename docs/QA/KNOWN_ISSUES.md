# Known issues

Status on 17 Nov 2026, after the QA round. Every bug below was found by running the product, and each fix has a test that would fail without it.

## Bugs found and fixed in this round

| # | Severity | Bug | Found by | Fix | Regression tests |
|---|---|---|---|---|---|
| B1 | **High** (business rule / security) | Agencies that are **not active** (pending KYC, expired documents, or **suspended**) could still add offers to the cart and book. The documented rule (KYC-4/5, TENANCY §74) was never enforced: `assertOrgEligible` existed but was not called. | `security/tenancy.service.spec.ts` | `cart.addOffer`, `cart.addManual` and `checkout.submit` now refuse staff of non-active organisations with `ORG_NOT_ELIGIBLE`. Customers are covered by the storefront's own seller check. | Unit test `organizations.test.ts` (suspended, pending KYC and expired documents). Service test. UI: `admin-management.spec.ts` "KYC: the platform approves a pending agency, which can then book". |
| B2 | **High** (customer stuck) | A customer who pressed Continue on the checkout review step quickly landed on the **staff-only "Choose a customer"** step, which was empty with Continue disabled, and could not book. The page assumed "staff" while the cart was loading. | `services/booking-per-service.spec.ts` (flight, activity) | The buyer type now comes from the session, which is known immediately. | `pages/checkout.ts` asserts the step never appears for customers, in every customer checkout test. |
| B3 | Medium | **Sub-agency → Compliance (KYC)** showed a loading skeleton forever. Sub-agencies have no KYC case of their own, so the backend answered "not found" and the page had no error state. | `smoke/smoke.spec.ts` (navigation crawl) | The page explains "Verified through your parent agency". Any other error shows the retry state. | Smoke crawl and `a11y/interaction.spec.ts` |
| B4 | Medium | **Promo codes could not be deactivated** in the UI (no status control, although the API supports it), and the discount value was labelled **"Markup"**. | `admin/admin-management.spec.ts` | A Status field was added to the promo dialog. The value is labelled "Discount" in the dialog and the table (English and Arabic). | Promo lifecycle test: create, persist, applied by the engine, deactivate, refused. |
| B5 | Medium (WCAG AA) | **Success toasts failed contrast**: green #008a2e on #ecfdf3 = 4.25:1, below 4.5:1. These are Sonner's built-in colours, which the page-level scans never saw because toasts are transient. | `a11y/interaction.spec.ts` (scan with the profile menu open) | Toasts now use the design system's status tokens, which are contrast-tested in light and dark. | Toast contrast tests in light and dark |
| B6 | Low (regressions from the previous round, caught before release) | The new `DateInput`'s minimum width pushed the birth-date field out of the traveller card. The supplier bulk-edit dates truncated the year. | Visa booking screenshot, stop-sell screenshot | Minimum width removed. No clear button on the always-set bulk dates. | Per-service bookings, supplier suite |

## Open items and limitations

| # | Area | Description | Impact | Workaround / next step |
|---|---|---|---|---|
| K1 | Demo backend | The in-browser backend stores a full snapshot just after each write. A page **reload in the moment between "Saved" and the store finishing** loses that write. | Demo only. A real backend commits before it replies. | Tests await the backend's "stored" broadcast (`nextPersist`). Making each write wait for the store added ~0.9 s per save, so it was not adopted. |
| K2 | WebKit | Safari reports Next.js route prefetches that a navigation cancels as console errors ("… `_rsc=` … due to access control checks"). | None for users: the prefetch is abandoned on purpose. | Filtered narrowly in `fixtures.ts`. |

A panel control could be added. |
